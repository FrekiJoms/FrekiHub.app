## Confirmed defects and implementation gaps

| ID / priority | Finding and evidence | Recommended scope |
| --- | --- | --- |
| S01 / High | **Percentage planner can save an amount its own backup restore rejects.** `RuleForm.save` (`lib/forms.dart:474`) bounds rate × quantity, while `project` (`lib/data.dart:654`) multiplies the actual income/expense base as well. The result converts from BigInt without validating the supported 9,000,000,000,000,000 minor-unit ceiling. Mark complete inserts that projected amount directly (`lib/budget.dart`). | Validate the final projection before conversion and again before committing an occurrence. Keep integer rounding and currency isolation. |
| S02 / Medium | **Restore accepts malformed log timestamps that break log rendering.** Raw `activityLogs` restore (`lib/data.dart:533`) does not validate field types/ranges. SQLite INTEGER affinity accepts a nonnumeric string; `LogsSheet` casts `event['time'] as int` (`lib/logs.dart:57`). | Validate log IDs, actions, JSON, types and supported epoch ranges before replacement; retain transactional rollback. |
| S03 / Medium | **An exported backup can exceed the restore limit.** `backup` (`lib/data.dart:387`) exports full history without a size cap; Settings restore rejects files above 20 MiB (`lib/settings.dart:130`). Existing F05 remains open. | Align export/import policies, preserving full history and atomic restoration. |
| S04 / Medium | **GPS acquisition delays the effective Home clock-in/out time.** `RecordLocation.commit` awaits permission and a location request before executing the save (`lib/services.dart:26`); `clockIn`/`clockOut` then sample the clock. Native lookup can wait 20 seconds, with a 25-second Dart timeout. This is a regression in the latest foreground capture implementation. | Capture the confirmed action instant before optional acquisition; only attach a sample compatible with that instant. |
| S05 / Medium | **Background session-start failures are swallowed.** `Automation.applySessionTransition` (`Automation.kt:134`) persists/emits the start before trying the foreground service, then ignores its exception. A record can exist without its native timer. Existing F03 remains open; real occurrence needs a phone. | Add observable diagnostics and a platform-compatible fallback without deleting the saved session. |
| S06 / Medium | **Native event storage grows without a retention bound.** `Automation.emit` (`Automation.kt:18`) parses and synchronously rewrites the entire SharedPreferences array; acknowledgement rewrites it again. Existing F04 remains open. | Design durable queue storage with explicit retention semantics; do not silently discard events or weaken commit-before-ack. |
| S07 / Medium | **Activity stream errors have no recoverable presentation.** `LogsSheet` (`lib/logs.dart:33`) never checks `snapshot.hasError`. Failure before the first snapshot leaves skeletons visible; failure after data can leave stale rows without an error. Existing F12 is still open, with updated behavior. | Persistent error/Retry state, retaining previously loaded records where appropriate. |
| S08 / Medium | **Location provider behavior differs by feature.** Map and foreground record capture use `MapLocation` with several providers. Syntax current-place lookup and background automation still call GPS-only-when-enabled `Automation.requestLocation` (`Automation.kt:77`, `MainActivity.kt:111`, `lib/syntax_builder.dart:141`). | Reconcile provider selection while preserving opt-in tracking, rule accuracy limits and original event timestamps. |
| S09 / Medium, policy gap | **Android system backup is not explicitly configured.** App and merged manifests have no explicit backup/extraction policy. The app's no-cloud-copy documentation is too broad: Android Auto Backup defaults can include preferences and database files when device backup is enabled. Runtime queues/session state also need a deliberate transfer policy. | Define intended cloud/device-transfer rules and update product wording. Actual backup transport was not inspected on a phone. See [Android Auto Backup](https://developer.android.com/identity/data/autobackup). |

S01 reproduction used a valid maximum-sized income, a 100% income-based rule and allowed quantity 100,000. The resulting expense was stored, then rejected by restore of that database's own export. The input rule passes the existing rate/quantity checks. This establishes a boundary defect, not a claim that ordinary-sized transactions overflow.

S02 reproduction restored a synthetic log with `time: "invalid-time"`; the database accepted it, and the same timestamp conversion used by the log UI threw a TypeError. No personal backup was used.

## Other current limitations

- Finance purchases detected while Flutter is closed remain queued until reconciliation; this is an implemented boundary, not an immediate native database commit (F02).
- Release configuration still uses debug signing. This is a release blocker, not a requirement to produce a release during this audit (F01).
- Calendar stores selection/view observations but initializes at today/month on remount. Day/week duration arithmetic needs separate DST navigation checks; Manila does not exercise that boundary (F08).
- Session editing still hard-codes `d MMM yyyy, HH:mm` instead of selected display formats (`lib/forms.dart:165`, F13).
- Map full-range queries materialize the complete selected history and marker groups. No physical-device long-history benchmark establishes scalability (F06).
- Logs cover session insertion/end and Finance insertion/meaningful update; they are not a journal of every deletion or autosave (F10).
- Existing cross-app pending clock-outs carry no fresh location payload. Replay must not acquire today's GPS and claim it describes the historical ending.
- Individual injected failures for every async mutation callback remain a coverage gap (F11). The older listed Finance/Settings callbacks now use `guarded`; that old wording should not be treated as proof they still lack a handler.

## Findings rechecked as resolved

The old Map record-stream recovery claim is superseded: the unchanged-row skip now requires `loadError == null`, and a successful snapshot clears it (`lib/map.dart:196`). Shared sheet behavior, explicit data-action success feedback, compact/expandable logs, skeleton policy, Home note batching and current foreground position capture have automated coverage in the passing suite. That does not substitute for real provider, background lifecycle or profile measurements.

Fix S01/S02 and the action-time regression first. Then address backup policy/size, recoverable errors and native delivery/queue behavior. Toolchain/dependency cleanup should follow a coordinated compatibility pass rather than automatic upgrades or mass lint suppression.
